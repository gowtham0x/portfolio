ZTL — Zero Trust Link

A next-generation adversary simulation framework — 14 modules, 20 stealth files, 9 native C/ASM modules, 4 C2 transports, in-memory .NET CLR host, CS-compatible BOF loader, and a polymorphic generator that produces a unique binary hash on every build.

ZTL

Context

Modern EDR solutions hook userland APIs, scan process memory, correlate behavioral sequences, and feed telemetry to cloud ML engines. Building an adversary simulation framework that operates inside a fully monitored environment requires low-level control that Rust alone — let alone Python or Go — cannot provide. ZTL was built from the ground up with a Rust core and native C/ASM stealth modules for the operations where even Rust's own runtime would become a detection surface.

The Problem

Off-the-shelf C2 frameworks (Cobalt Strike, Sliver, Havoc) are signatured and caught within seconds. Building one that evades Ring 3 userland hooks, in-memory YARA scans, ETW telemetry, and kernel-level EDR callbacks requires understanding the Windows security model at the level that EDR vendors think about it — and then engineering around every layer in the correct order.

Process

01

Two-phase startup — native surgery before the async runtime

NTDLL unhooking temporarily marks .text as PAGE_READWRITE — not executable. If a Tokio worker thread calls into ntdll at that moment the process crashes. Solved by running all native ops synchronously in main() before the runtime starts: NTDLL unhook, direct syscall init, GhostStack, HWBP, Foliage. The 9-stage async stealth init then delays each subsequent operation — sandbox check, EDR scan, ETW patch, BYOVD, privilege escalation, persistence — by 30 seconds to 10 minutes, defeating behavioral correlation engines that look for rapid sequences.

02

20 stealth files + 9 native C/ASM modules

GhostStack (ghoststack.c + ASM) spoofs the thread call stack using RDTSC-encrypted heap backup so EDR stack-walk sees a benign pool thread. HWBP (hwbp_bypass.c) patches AMSI and ETW via CPU debug registers DR0–DR3 — no memory writes, no detectable byte modifications. Foliage (foliage_sleep.c) APC-queues RC4 encryption of the .text section during sleep so memory scanners find encrypted data, not shellcode. PEB resolver (peb_resolver.c) walks the loader with CRC32 hashing to resolve WinAPI addresses with zero static imports. Header stomper zeros the PE header post-load — defeats YARA and pe-sieve in-memory scans.

03

4-transport C2 · 5 malleable profiles · per-session AES-256-GCM

comms.rs supports HTTP/S, DNS, SMB named pipes, and raw TCP — each with 5 malleable profiles that disguise beacon traffic as Microsoft Update, generic JSON APIs, and other benign patterns. Every agent gets a unique ephemeral AES-256-GCM key; session compromise exposes nothing else. Beacon intervals randomise with per-session jitter. The operator interface is Telegram Bot API — no exposed C2 server, no suspicious HTTP callbacks, traffic indistinguishable from normal HTTPS. ngrok punches through NAT; offline-first connectivity monitor auto-reconnects and recreates tunnels on drop.

04

In-memory .NET CLR host + CS-compatible BOF loader + polymorphic generator

dotnet_engine.rs hosts the .NET CLR inside the Rust process via raw COM interop — no fork-and-run, zero child process noise, AMSI and ETW pre-patched before execution. bof_engine.rs parses raw COFF .obj files, resolves relocations, bridges 20 Beacon API functions in Rust, and wraps execution in a native SEH crash guard so a bad BOF cannot kill the agent. agent_generator.rs produces 9 payload formats with polymorphic transforms and BUILD_PADDING random bytes — unique binary hash every build, defeating Kaspersky KSN cloud hash lookup.

Design Decisions

Rust + native C/ASM hybrid — not pure Rust

Rust's stdlib allocator and runtime leave detectable stack frames and heap patterns. NTDLL unhooking, APC queueing, direct syscall stubs, and call stack manipulation require exact memory layout that rustc cannot guarantee across optimization passes. C and hand-written ASM give surgical control for those 9 native modules while Rust handles all orchestration, crypto, comms, and business logic safely.

Strict phase order: ETW → BYOVD → persistence

Persistence writes (registry Run key, scheduled task, WMI subscription) are high-confidence EDR triggers. BYOVD loads the Warsaw_PM vulnerable driver to null EDR kernel callbacks — making the system blind before registry writes happen. But driver loading itself generates telemetry, so ETW must be patched first. The sequence is strictly ordered: each phase removes the sensor layer that would detect the next one.

Reflection

“ZTL is the project where I stopped thinking like a tool user and started thinking like a platform architect. Every layer — crypto, comms, stealth, persistence, privilege escalation — had to compose correctly in the right sequence or the system collapses at the worst possible moment. The constraint of not being detected forced me to understand the Windows security model at the depth that EDR vendors think about it. That is exactly the perspective that matters in offensive security research.”
